## §1 TTS 站（配音）

### 1.1 edge-tts（现用主力）
- 官方定位原文："allows you to use **Microsoft Edge's online text-to-speech service**"；"WITHOUT needing Microsoft Edge or Windows or an API key"【A1】。
- **性质=云端免费接口，非本地推理**【A1】——与 CEO「本地算力优先」令的偏差点，须如实记账（当前账目零云支出，但推理算力在微软侧）。
- 参数面（官方 CLI）：`--rate ±%`、`--volume ±%`、`--pitch ±Hz`、`--voice`、`--list-voices`、`--write-media`、`--write-subtitles`（可直接产 SRT）【A1】。
- 供给风险原文："Support for custom SSML was removed because **Microsoft prevents** the use of any SSML that could not be generated by Microsoft Edge itself…the service only permits a single `<voice>` tag with a single `<prosody>` tag"【A1】——微软在主动收紧该免费接口能力面。
- 许可证 GPL-3.0；仓库 12k stars / 312 commits【A1】。

【推论】①接口随时可能被微软进一步收紧/关停（SSML 移除即先例），**本地替代备份=Piper 系**（见 1.2），R-B 必须真装真测；②`--write-subtitles` 产 SRT 可与 R-C（faster-whisper 对轴）互补——TTS 自带词级时间戳 vs STT 反推，两路 PoC 对比后择优；③负值参数须写 `--rate=-50%` 连写式【A1】，写进 R-B 参数表。

### 1.2 Piper 系（纯本地替代·R-B 备份线）
- 旧仓 rhasspy/piper 官方横幅："**This repository was archived by the owner on Oct 6, 2025. It is now read-only.**" + "Development has moved: https://github.com/OHF-Voice/piper1-gpl"【A2】。
- 后继仓 OHF-Voice/piper1-gpl：官方定位原文 "A fast and local neural text-to-speech engine that embeds espeak-ng for phonemization"；安装 `pip install piper-tts`；许可证 **GPL-3.0**；5.7k stars / 289 commits【A3】。
- **维护风险信号（原文）："LOOKING FOR MAINTAINERS — The Open Home Foundation is looking for maintainers for Piper!"**【A3】——备份线的长期可用性风险，如实记账。
- 中文语音：旧仓官方 VOICES.md 收录 `zh_CN huayan`（x_low + medium 两档，模型托管 HuggingFace rhasspy/piper-voices v1.0.0）【A4】。后继仓是否沿用同一语音库未采（§6）。
- 许可证注意：Piper 旧仓 MIT、后继 GPL-3.0【A2/A3】——我们以内部生产工具使用（不分发其二进制）无许可冲突；edge-tts 同为 GPL-3.0【A1】。

【推论】R-B 备份验证对象应从「Piper」更名为 **piper1-gpl（pip piper-tts）**，zh_CN huayan（medium 档）为候选试配音；若 medium 档试听不达人设卡嗓音要求，本地备份线结论=「可用性存疑」，如实报 CEO 不硬撑。

## §2 STT 站（字幕对轴）

faster-whisper 官方 README 基准（同精度比 openai/whisper "up to 4 times faster…while using less memory"，int8 量化 CPU/GPU 双支持）【A5】：

| 场景 | 档位 | 耗时（13 分钟音频） | 显存/内存 | 证据 |
|---|---|---|---|---|
| GPU（RTX 3070 Ti 8GB·CUDA12.4）large-v2 | fp16 | 1m03s | 4525MB | A5 |
| GPU large-v2 | **int8** | 59s | **2926MB** | A5 |
| GPU large-v2（batch=8） | int8 | 16s | 4500MB | A5 |
| CPU（i7-12700K 8 线程）small | fp32 | 2m37s | 2257MB RAM | A5 |
| CPU small | **int8** | 1m42s | **1477MB RAM** | A5 |

- large-v3 官方支持（示例代码 `model_size = "large-v3"`）；词级时间戳 `word_timestamps=True`；VAD 滤波（Silero）内置【A5】。
- 依赖面：Python 3.9+；**不需要系统装 FFmpeg**（音频解码走捆绑 FFmpeg 库的 PyAV）；GPU 执行需 cuBLAS(CUDA12)+cuDNN 9【A5】。许可证 MIT【A5】。

【推论】①本机当前空闲显存 1.5GB（M1）< large int8 的 2926MB 实测需求（A5）→ **现在就走 CPU int8 路线**（small int8 仅 1477MB RAM，9950X 上更稳）；GPU 档留到显存窗口≥3GB 再切，与 m2 §2 分时纪律一致；②60s 口播≈1 分钟音频量级，CPU int8 耗时按 13min/1m42s 线性外推≈秒级-十秒级【推论·待 R-C 实测定数】。

## §3 文生图/视频站（后置升级路线）

- ComfyUI 官方定位原文："**The most powerful and modular AI engine for content creation**"；节点图工作流；原生支持模型清单含 SD1.5、**SDXL**、SD3.5、Flux.1/2、**Qwen Image**、Hunyuan Image 2.1 等（图像）与 **Wan 2.1/2.2**、LTX-Video、HunyuanVideo、CogVideoX 等（视频）【A6】。
- 显存管理原文："Efficient local execution with asynchronous queueing, partial graph re-execution, **smart VRAM and RAM management, model offloading, and support for quantized models**"；离线原文："**Runs fully offline**: core does not download anything unless you request it. Use `--disable-api-nodes` to disable the optional paid Comfy API nodes"【A6】。
- Windows 官方发行：N 卡便携包（支持 20 系及以上，自带 python 3.13 + pytorch cuda 13.0）+ 桌面应用；许可证 **GPL-3.0**【A6】。
- **当前 README 无固定最低显存数字声明**（旧版「<3GB 也可跑」类措辞已不在现文）——具体 N 卡选购建议在官方 wiki「Which GPU should I buy」页，本轮未采（§6）【A6】。

【推论】①ComfyUI 装机本身零预算可行（官方便携包），但**当前空闲显存 1.5GB（M1）远不足以跑 SDXL 级**——后置决策（等首发数据+显存窗口≥6GB 分时）维持不变，与 m2 §1 一致；②若未来走国产画面路线，Qwen Image/Wan（视频）在原生支持清单内【A6】，与集团「国产大模型亲和」受众叙事同向（受众对位见 research/user-research §2.3）——此为选题级推论，不作承诺；③`--disable-api-nodes` 开关可保证付费云节点不混入，符合零预算纪律【A6】。
