## §2 调用纪律

1. **一键调用**：`call_expert.py`（材料=文件传入·登记表+提示词外置数据件）——会话/循环/任何人皆可调，无需装配。
2. **调用必落账**：expert-calls.md 自动追加一行（时间/身份/材料/结论首行）——评审记录不可改写（dept-review-mechanism §6 同律）。
3. **双通道**：例行=本地 Ollama 独立调（零 token·异构无创作者偏见）；复杂裁决=交互会话按专家立场评（挑刺优先）+必要时双跑对照。
4. **效率平衡**（O-2248）：调用按需不排队——测试件=机检+抽样调用；进链件=环节门席调用；连续超预算=机制自审（dept-review §5 B5）。
5. **席位专家与环节门**：S0-S6=dept-review-mechanism §1 同一身份（名册=人的到位·环节门=流程的到位）；E1-E8 终审团=公司级终审席（dept-review-mechanism §6·不属部门名册）。

## §3 与既有法的关系

- dept-review-mechanism：环节门=流程位·本名册=专家位（两件配套=「安排专职」+「机制把关」）。
- 终审团正典=dept-review-mechanism §6（P-62 ① 起·原 review-panel v1.5 同日退役为指针）；名册席位专家=其前置环节门的执行者。
- O-2241 Token 纪律：本地 Ollama 调用=零 API；例行调用不占会话 token。
- U171 人设域纪律（集团）：职能身份·不虚构人名——真人人设（如出镜人物）=CEO 域。
