# BigStream 部门专家评审机制（Departmental Expert Review）

> CEO 令 O-20260923-2245-bm-a：「制定部门专家评审机制，提升每个环节品质」；v1.1 校准令 O-20260923-2248-bm-a：「你也不能审到效率产出低下，要平衡」。
> **定位**：评审团（review-panel）=发布前**终审**；本机制=**环节门**——每个生产环节由归口部门设专家席把关，环节质量不推给终审兜底。环节门全过+终审全席 ≥9=完整放行链。**效率平衡条款（§5）=机制的另一半**：审到点上，不审到瘫。
> 级别：L2 机制（T2·7 天否决窗）。
> Token 纪律（O-2241）：机检零 token 先行——专家席只审机器测不了的（品味/语感/策略判断）；任一席可由**本地 Ollama qwen2.5:14b** 独立评审（零 API·命令入台账）；会话专家按「挑刺优先」立场评。

## §2 门槛分级（与 CEO「都要 9 分」对齐）

- **进链件**（走向发布的每环节工件）：环节席 0-10 分制，**≥9 过门**，任一红线=0 分一票否决；短板=该环节整改清单（附台账行）。
- **测试件**（O-1756 允许的单件过链 PoC）：机检全过=入台账；专家席**抽样**评审（迭代期每版可评=现行实践），不设全件 9 分硬门（未上线=未测量的诚实态）。
- **终审团**（review-panel 七席）：环节门全过之后最后一关，全席 ≥9=放行候选——环节门抬高质量地板，终审审整体成品感。

## §3 评审流程（四步·每环节）

1. **机检先行**：该环节机检前置全绿才进专家面（FAIL=直接打回重做，不占专家注意力）；
2. **专家盲评**：归口席独立评（挑刺优先：职责=找理由打回）；Ollama 独立评审可选（命令实录入台账）；
3. **落账**：`docs/reviews/station-reviews.md` 追加一行（环节/件/席/分/短板/verdict/证据指针）——评审记录不可改写；
4. **整改闭环**：verdict=整改 → 清单回写该环节工件来源处，重评通过才放行下一环节。

## §5 效率平衡条款（v1.1 · CEO 令 O-20260923-2248-bm-a「你也不能审到效率产出低下，要平衡」）

> 评审机制的目的=提品质**保吞吐**。红线面永不放松；打磨面设预算——审到点上，不审到瘫。

| # | 条款 | 规则 |
|---|---|---|
| B1 | **并行评审** | 同件多席一轮并行评完，短板**合并成一张整改清单**一次改——禁逐席往返挤牙膏 |
| B2 | **返工预算** | 环节门整改 ≤1 轮合并清单；终审返工 **≤2 轮**，第 2 轮仍 FAIL=升 CEO 裁置（放行降级 或 弃件换题·沉没成本禁令）——杜绝无限打磨环 |
| B3 | **评审 SLA** | 环节评审当轮或 ≤24h 闭环，禁压件过夜积压 |
| B4 | **批量共享** | 量产批内：同骨架变体共享母件环节结论，变体只做轻量复检（平台语态+规格窗），不逐件全门重审 |
| B5 | **机制自度量** | 台账记「评审轮次/件」与「单件过链评审时长」；**连续两批超预算=机制自审**（门槛或流程失衡即修法） |
| B6 | **红线豁免** | 合规五条/真实律/AIGC 标识/脱敏面**永不参与平衡**——效率预算只作用于质量偏好面（品味/打磨/语感） |

**迭代定性参照**（2026-09-23 实况）：当日 v3→v10 八轮迭代全部由 CEO 方向令触发（文案→工艺→意思→评审团→视觉→赛博→去AI感·每次=新方向），不属机制空转；但 B2 自此立法——**同方向打磨 ≤2 轮**即升裁，防方向既定后的无限精修。
