# BigStream 内容生产线（Content Pipeline）

> 一条内容从选题到复盘的标准流程。每个环节有门禁；不过门=不流转，无例外。
> 当前形态：AI 生产线（AIGC）+ CEO/文化分管终审；账号开通前一切产出为草稿库阶段。

## 流程图

```
M0 选题库 → M1 脚本/文案 → M2 素材制作 → M3 多平台适配 → M4 合规审查门 → M5 发布/排期 → M6 数据回流复盘
 data/ideas   data/drafts    AIGC 工具链     一稿多变体       机审+人审         账号到位后       周复盘台账
```

## M0 选题库（`data/ideas/ideas.md`）

- 一行一题，追加式：`编号 | 日期 | 赛道 | 选题 | 钩子（一句话） | 来源（可溯） | 状态`
- 来源律：每个选题必须能回答「这个说法/数据从哪来」——集团三公司实况数据（git/台账/面板）天然合规且独家。
- 选题密度：主赛道优先；AI 每周提案批，CEO 批注后转 M1。

## M1 脚本/文案（`data/drafts/`）

- 按目标平台写主稿（短视频脚本=口播词+分镜提示；图文=全文）。
- 命名：`YYYYMMDD-<选题编号>-<平台>-<vN>.md`；版本不改旧件，新开 vN+1。

## M2 素材制作（AIGC 工具链）

- 配音：TTS 工具（人设定嗓后锁定音色参数）。
- 画面：文生图/截屏实录（集团真实系统界面=最强素材，注意脱敏：无密钥无内网信息）。
- 剪辑：脚本驱动的时间线模板；`src/` 落自动化脚本（如批量字幕、转码、封面合成）。
- **视觉规格**（O-20260923-1937-bm-a）：一切画面产出（字卡/字幕/封面/实录剪辑）按 `docs/visual-spec.md` 五律执行——字重层级律（一卡一 H1 锚点·H1/H2/H3 字重字号双拉开）/42% 视觉中心构图网格/色彩律（黑底白字+FLUX 白金强调）/动态律（150ms 淡入出）/首帧律（首帧 3 秒=封面级）；分镜表「画面」列必须按规范填 H1 锚点字+层级+构图位。渲染器排版引擎已内置双字重栈（`src/render/render_card_video.py`）。
- 工具选型：先零预算链路（本机 ComfyUI / Ollama / 开源剪辑 CLI），不满足再报 CEO 批预算。

## M3 多平台适配（一稿多变体）

同一内容 → 各平台变体（规格见 `docs/platform-playbook.md`）：时长裁切、画幅（9:16/16:9/1:1）、标题改写、标签、封面。变体登记在草稿头部（母稿链接）。
- **视觉检查点**（O-20260923-1937-bm-a）：画幅改版后重过 `docs/visual-spec.md` §2 构图网格（按目标画幅适配安全边距/视觉重心）；封面/首帧按 §5 封面级必审（E7 席）。

## M4 合规审查门（发布前置·硬门）

1. **红线机审**：标题党检测（标题承诺 vs 内容交付逐项对表）、来源引用完备性（无来源断言=拦）、数据真实性（引用集团内部数据须与 git/台账实况一致）。**已工具化**：`python src/draft_lint.py`——结构完备/密钥与内部信息脱敏扫描/AIGC 声明/来源数/量化风险声明/口播时长估算，FAIL=禁过门；lint 全绿=机审必要条件而非充分条件（语义对表仍归人审）。
1.5 **工艺审核层**（O-20260923-1918-bm-a）：①语气情感=分句情感参数表（`src/render/emotive_tts.py`·九档 profile·抑扬顿挫实测件=bs-001-v3）；②剪辑卡点=一拍一卡、卡切对齐口播词边界（`voiceover-v3.beats.txt` 三栏拍稿制）；③BGM=轨位常备+人声 ducking（音量不压人声·合成零预算拍）；④铁律自检表（copy-craft §3）随稿；⑤**视觉审**（O-20260923-1937-bm-a）=按 `docs/visual-spec.md` 逐条对表（字重层级/构图网格/色彩律/动态律/首帧律——首帧 3 秒=封面级必审）。**快评回路**：CEO 小步快迭代——单件垂直切片→快评→修→再呈，不等周轮。成品要件缺一=不过门。
2. **AIGC 标识**：中国境内依法显著标识 AI 生成；各平台按其规则标注。
3. **脱敏审**：画面/字幕无密钥、无内部路径敏感信息、无未公开竞品数据。
4. **嗓音人审**：文化分管（Qiqi）或 CEO 抽样终审——账号开通前的草稿阶段=抽样审；上线后按 CEO 定节奏。
4.5 **专家评审团门**（O-20260923-1927-bm-a·CEO 令「所有的都要9分才放出来」）：**章程与现行法度以 `docs/dept-review-mechanism.md` §6 为单一真相**（P-62 ①·2026-09-24 起；八席盲评=E1 爆款操盘手/E2 文案大师/E3 平台算法官/E4 直觉观众/E5 合规官/E6 CEO 代言人/E7 视觉设计官/E8 剪辑工艺官·原 review-panel 已退役为指针）——木桶原则全席 ≥9 才放行，任一席 ＜9=FAIL 打回；E4 双态制（CEO 裁「真人实测为 E4」）：开发期（账号未开）门槛执行=**七席（E1/E2/E3/E5/E6/E7/E8）全 ≥9 即「放行候选」**·E4=Ollama 参考仪（读数不作拦截·只作迭代输入）；上线后 E4=平台真人实测数据执行 9 分线。台账=`docs/reviews/`（追加式·分数史=质量爬坡曲线）。CEO 意见＞评审团（否决权恒在）。
5. 门禁结论落草稿尾部：`GATE: PASS/FAIL + 日期 + 审者`。FAIL=整改后重过门，禁带病流转。

## M5 发布/排期（账号到位后）

- 通道现实：多数平台无公开发布 API——公众号有草稿接口（需 AppID）、YouTube Data API 可用、B站/视频号/微博=草稿箱+手动/半自动（详见 platform-playbook）。
- 排期：发布台账 `output/schedule.md`（一行：日期|平台|内容|状态|链接）。
- 发布=账号物理件就绪 + M4 PASS 双前置。

## M6 数据回流复盘（`output/analytics.md`）

- 周更一行制：各平台后台导出数据 → 与发布台账对账 → 涨粉/播放/互动率/完播 → 下周选题修正。
- 诚实纪律：未上线=未测量；数据只来自平台后台导出，禁拍脑袋。
